# Аудит исходного прототипа

Базовая точка фиксации: commit `6e6a4d5` (`Load director direction reminder layer`, 12 сентября 2026). Перед изменениями рабочее дерево было чистым.

## Как работало приложение

`index.html` загружал `styles.css`, затем пять `mobile-fixes*.css`. JavaScript загружался как classic scripts в строгом порядке: `app.js`, `v11.js`, `v111.js` … `v149.js`. Сборщика, package manifest, API, сервера и автоматических тестов не было.

`app.js` создавал глобальный `state`, функции страниц и inline `onclick`. `v115.js` после нескольких промежуточных render очищал демоданные, поэтому фактическая рабочая версия стартовала пустой. Данные не сохранялись в localStorage/IndexedDB и исчезали при перезагрузке.

Все файлы из `index.html` реально исполнялись. Это не набор неиспользуемых вариантов: поздние файлы захватывали предыдущие функции в `previous.../before...` и оборачивали их. Удалить отдельный патч без анализа цепочки было нельзя.

## CSS

Исходный `styles.css` содержал базовый desktop/mobile слой, календарь и последующие уточнения тех же селекторов. Пять mobile-файлов загружались после него и исправляли ширины, grid, модалки, iOS date inputs, sticky teacher view и overflow. Итог зависел от каскада одинаковой специфичности.

Каскад объединён в `src/ui/styles.css` в исходном проверенном порядке. Удалены шесть отдельных подключений и риск случайной перестановки. Визуальные значения и UX намеренно не менялись. Дальнейшая семантическая чистка повторных селекторов требует screenshot-regression на реальных контрольных размерах и вынесена после появления устойчивого test-окружения.

## Обнаруженные риски и исправления

- Не было автоматического контроля финансовых правил. Добавлен независимый доменный модуль и тесты.
- Не было границы данных: UI напрямую менял глобальные массивы. Добавлен API client и описан поэтапный перенос; текущий UI пока остаётся in-memory.
- Не было защиты повторных серверных команд. В схеме и API заложены idempotency keys и уникальное списание на attendance.
- История цен существовала как несколько ad-hoc полей/лотов. В MySQL она нормализована в price versions, snapshots, ledger и lots.
- Родитель в прототипе был строкой в карточке ребёнка. В БД это отдельные guardians и many-to-many связь, пригодная для будущей роли parent.
- GitHub Pages workflow разворачивает только публичный статический прототип. Он не годится для CRM с данными и не должен получать секреты.
- Диапазоны зарплаты, партнёрского расчёта и статистики были зашиты на август–сентябрь 2026. При последующих датах новые операции молча не попадали бы в отчёты. На свежей загрузке legacy-значения теперь заменяются текущим месяцем/днём; выбранный пользователем диапазон не перезаписывается.
- Push в `main` автоматически публиковал прототип на GitHub Pages без test-gate. Workflow оставлен только для ручного preview; CI теперь запускает проверки отдельно.

## Ограничение текущего этапа

Консолидация JS сохраняет последовательную семантику исходных обёрток внутри одного файла, чтобы не менять согласованный UX без browser regression infrastructure. Полное удаление внутренних совместимых обёрток следует выполнять по страницам одновременно с подключением собственного API и e2e-снимками на test.
