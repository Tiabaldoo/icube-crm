# Правила для «Острова чудиков»

План и утверждённые решения — в `GAME_PLAN.md`. Если правило здесь расходится с запросом, остановись и спроси владельца.

## Границы кода
- Код игры — только в `game/`. Изменения CRM — только перечисленные в `GAME_PLAN.md` (доступ ребёнка, внутренний API) и только под флагом `GAME_ENABLED`.
- Не менять cookie, маршруты и правила входа CRM для взрослых ролей.
- Код в `game/` не подключается к базе CRM; данные CRM — только через внутренний API. Импорт из `backend/` и `database/` запрещён без исключений.
- CRM не импортирует код из `game/`.

## Детский доступ
- Сессия CRM ребёнку не выдаётся. Роль `child` не добавляется в проверки `login` и `authenticateToken`.
- Детская учётка — отдельный пользователь ровно с одной ролью `child`. К взрослому пользователю роль `child` не добавляется.

## Базы и миграции
- Не создавать файлы в `database/migrations` и не запускать `npm run migrate`.
- Миграции игры — только в `game/migrations`, только для `icube_game_test`.
- Без `DROP`, `TRUNCATE`, массовых `DELETE`/`UPDATE`.

## Production и сервер
- Никогда не использовать `.env.production`, `APP_ENV=production`, `icube_prod`.
- Не подключаться к серверу и базам. Команды для сервера готовятся в репозитории, выполняет их владелец.

## Экономика игры
- За посещения начисляются звёзды, а не монеты. Монеты остаются внутриигровой валютой и с CRM не связаны.
- Существующая экономика игры сохраняется; числа берутся из конфигурации игры, новые не придумываются.

## Git
- Работать в ветке `feat/game`; в `main` не коммитить напрямую.
- PR в `main` сливает только владелец или по его явному подтверждению.
- Выполнять только этап, названный владельцем; к следующему этапу не переходить автоматически.
- Перед PR: `npm test` и `npm run check`.
